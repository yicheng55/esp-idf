## 📌 快速參考

### 當前配置（請以實際編譯為準）

`PTP_NETWORK_TRANSPORT` 是 compile-time 選項，可用「修改檔案」或「Compiler Define 覆蓋」。

目前此 repo 內 `constants.h` 的預設值為：

```c
// middlewares/3rd_party/ptpd-2.0.0/src/constants.h
// #define PTP_NETWORK_TRANSPORT 1 /* TRANSPORT_UDP_IPV4 */
// #define PTP_NETWORK_TRANSPORT 3 /* TRANSPORT_IEEE_802_3 */
#define PTP_NETWORK_TRANSPORT 4    /* TRANSPORT_IEEE_802_1AS（預設） */
```

### 配置詳情（不同 transport 的重點差異）

> 實際值來自 `middlewares/3rd_party/ptpd-2.0.0/src/constants.h` 與 `src/ptpd.c` 的執行期覆寫邏輯。

| 項目 | `TRANSPORT_UDP_IPV4` (1) | `TRANSPORT_IEEE_802_3` (3) | `TRANSPORT_IEEE_802_1AS` (4) |
|------|--------------------------|----------------------------|------------------------------|
| **封裝** | UDP / IPv4 | Ethernet L2 | Ethernet L2 |
| **EtherType** | —（走 IP） | `0x88F7` | `0x88F7` |
| **目的 MAC** | —（依 IP multicast） | `01:1B:19:00:00:00` | `01:80:C2:00:00:0E` |
| **`transportSpecific` / `majorSdoId`** | `0x0` | `0x0` | **`0x1`** |
| **`twoStepFlag`** | `FALSE`（可改） | `FALSE`（可改） | **`TRUE`**（強制） |
| **`delayMechanism`** | `E2E` / `P2P` 可選 | `E2E` / `P2P` 可選 | **強制 `P2P`**（由 `ptpd.c` 覆寫） |
| **`logAnnounceInterval`** | `1`（2 s） | `1`（2 s） | **`0`（1 s）** |
| **`logSyncInterval`** | `0`（1 s） | `0`（1 s） | **`-3`（125 ms）** |
| **`logMinPdelayReqInterval`** | `1`（2 s） | `1`（2 s） | **`-2`（250 ms）** |
| **`announceReceiptTimeout`** | `6` | `6` | **`3`** |

#### gPTP 專屬的執行期行為（由 `ptpd.c : PTPd_Init()` 套用）

```c
if (rtOpts.transportType == TRANSPORT_IEEE_802_1AS)
{
    rtOpts.delayMechanism          = P2P;
    rtOpts.announceInterval        = DEFAULT_ANNOUNCE_INTERVAL_8021AS;   /* 0 */
    rtOpts.syncInterval            = DEFAULT_SYNC_INTERVAL_8021AS;       /* -3 */
    rtOpts.clockQuality.offsetScaledLogVariance = DEFAULT_CLOCK_VARIANCE_8021AS;
}
```

> **注意**：gPTP 的 `logMinPdelayReqInterval` 是在 `bmc.c : initData()` 根據 `transportType == 4` 選用 `DEFAULT_PDELAYREQ_INTERVAL_8021AS`；其餘 1588 預設則直接沿用。

## ✅ 驗證清單

啟動後請確認以下訊息：

### 1. PTP 初始化
```
PTPd_Init: transportType=4 (1=UDP/IPv4, 3=802.3, 4=802.1AS)
```
✅ 確認 `transportType` 符合你編譯的 transport

### 2. 網路層初始化
```
netInitL2: registered L2 RX callback, transport=4
```
✅ 確認使用 Layer 2 模式，transport=4

### 3. 狀態轉換
```
state PTP_LISTENING
→ state PTP_UNCALIBRATED   (BMC 判為 Slave)
→ state PTP_SLAVE          (offset < DEFAULT_CALIBRATED_OFFSET_NS)
```
✅ 確認進入 SLAVE 模式

> 若本節點被選為 Master，則會：
> `PTP_LISTENING → PTP_PRE_MASTER → PTP_MASTER`
> 並開始週期性送 Announce / Sync / FollowUp / PDelayReq。
> 詳見 [`gptp_peer_delay_master.md`](gptp_peer_delay_master.md) §2 與 §6。

### 4. 時鐘同步（僅 Slave 模式會出現）
```
updateClock: offset from master:     0 s   XXX ns, drift:   XXX ns, peer delay: XXX ns
```
✅ 確認 offset 逐漸收斂至 < 1 µs

> `updateClock()` 只在 `handleSync()` / `handleFollowUp()` 的 `PTP_SLAVE` / `PTP_UNCALIBRATED` 分支被呼叫；
> Master 模式下即使有計算 `peerMeanPathDelay`，也不會觸發此 `printf`。
> （見 [`gptp_peer_delay_master.md`](gptp_peer_delay_master.md) §5）

## 🚨 故障排除

### 如果無法同步

1. **檢查配置**
   ```c
   // 在 constants.h 中確認：
   #define PTP_NETWORK_TRANSPORT TRANSPORT_IEEE_802_1AS
   ```

2. **檢查編譯輸出**
   - 重新編譯後確認 transportType=4
   - 如果仍顯示 transportType=3，請 Clean + Rebuild

3. **檢查網路與 Master 兼容性**
   - Master 設備是否支援 802.1AS (gPTP)
   - 使用 Wireshark 確認有 PTP 封包 (ether proto 0x88f7)
   - **重要**: 確認 Master 發送的目的 MAC 為 `01:80:C2:00:00:0E`
   - 檢查 Master 的 transportSpecific 欄位是否為 0x1

4. **檢查硬體**
   - DM9058 SPI 通訊是否正常
   - Link Status 是否為 UP
   - DHCP 是否成功分配 IP

## 💡 提示

### 何時使用 802.3 模式
- ✅ 與標準 PTPv2 設備同步
- ✅ 需要最大兼容性
- ✅ Master 設備類型未知

### 何時使用 802.1AS 模式
- ✅ Master 明確支援 gPTP (當前配置)
- ✅ 需要 802.1AS profile 的特定功能
- ✅ 網路環境為 TSN (Time-Sensitive Networking)
- ⚠️ 需要更快的同步速率 (125ms vs 1s)

**目前配置**: 使用 **802.1AS 模式** ⚙️

**重要提醒**:
- 🔴 確保 Master 設備支援 IEEE 802.1AS (gPTP)
- 🔴 使用 Wireshark 驗證 Master 發送的 MAC 地址為 `01:80:C2:00:00:0E`
- 🔴 如果同步失敗，可能需要改回 802.3 模式
