# ptpd `PTP_NETWORK_TRANSPORT` 三種 Transport 設定分析

> 參考來源：
> - [ptpd/ptpd (GitHub)](https://github.com/ptpd/ptpd)
> - [richardcochran/linuxptp (GitHub)](https://github.com/richardcochran/linuxptp)
> - linuxptp `configs/gPTP.cfg`
> - IEEE 1588-2008 / IEEE 802.1AS-2011 標準

---

## 一、概述

根據 ptpd 原始碼（`src/dep/constants_dep.h`）以及 linuxptp 的 `gPTP.cfg` 配置範例，PTP 的網路傳輸層在 IEEE 1588-2008 標準下定義為三種主要型態。在 ptpd 中以 enum `NetworkProtocol` 來定義：

| Enum 名稱 | 值 | 說明 |
|----------|----|------|
| `UDP_IPV4` | 1 | UDP over IPv4（預設，最常見） |
| `UDP_IPV6` | 2 | UDP over IPv6 |
| `IEEE_802_3` | 4 | 原生 L2 Ethernet |

而 **802.1AS (gPTP)** 並不是一個獨立的 `NetworkProtocol` 值，而是在 L2 transport 基礎上，疊加一組特殊參數（`transportSpecific=0x1`、強制 P2P、特定 MAC 位址等）所構成的 **profile**。

├────────────────┼────────────────┼────────────────┤
│  Ethernet      │  Ethernet      │  Ethernet      │

| **ptpd enum 值** | `UDP_IPV4` (1) | `IEEE_802_3` (4) | L2 + gPTP profile flag |

## 四、linuxptp 配置範例對照

### 4.1 UDP/IPv4（預設）

使用 `-4` 參數或不指定，預設即為此模式：

```bash
ptp4l -i eth0 -m          # 預設即 UDPv4
ptp4l -i eth0 -4 -m       # 明確指定
```

配置檔（多數沿用 default.cfg，無需覆寫）：

```ini
[global]
network_transport    UDPv4
delay_mechanism      E2E
```

### 4.2 IEEE 802.3 L2

使用 `-2` 參數，僅需切換 transport：

```bash
ptp4l -i eth0 -2 -m
```

配置檔：

```ini
[global]
network_transport    L2
delay_mechanism      E2E        # 或 P2P
ptp_dst_mac          01:1B:19:00:00:00
p2p_dst_mac          01:80:C2:00:00:0E
```

### 4.3 IEEE 802.1AS (gPTP)

使用官方 `gPTP.cfg`，這是與其他兩者差異最大的一組：

```bash
ptp4l -i eth0 -f gPTP.cfg -m
```

完整 gPTP 配置（摘自 linuxptp `configs/gPTP.cfg`）：

```ini
[global]
gmCapable                1
priority1                248
priority2                248
logAnnounceInterval      0
logSyncInterval          -3
syncReceiptTimeout       3
neighborPropDelayThresh  800
min_neighbor_prop_delay  -20000000
assume_two_step          1
path_trace_enabled       1
follow_up_info           1
transportSpecific        0x1
ptp_dst_mac              01:80:C2:00:00:0E
network_transport        L2
delay_mechanism          P2P
```

## 五、關鍵設計理念差異

### 5.1 `transportSpecific = 0x1` 是 802.1AS 的「身分標籤」

- 純 1588 節點看到 `transportSpecific` 不符會 **直接 drop 該封包**
- 因此 802.1AS 與一般 1588 設備 **天然不相容**（即使 EtherType 都是 0x88F7）
- 對應 ptpd 原始碼中 `msg.c` 的過濾邏輯：
  ```c
  if ((header->transportSpecific & 0x0F) != port->transportSpecific)
      return -1;   /* drop */
  ```

### 5.2 `delayMechanism` 強制 P2P

- **802.1AS** 用 `Pdelay_Req / Pdelay_Resp / Pdelay_Resp_Follow_Up` 量測「鄰居間」延遲
- 每個 bridge 必須是 **PTP-aware**，扮演 boundary clock 角色
- **UDP/IPv4** 則多用 E2E (`Delay_Req / Delay_Resp`)，可穿透非 PTP-aware 的 switch
- **L2 default profile** 兩者皆可

### 5.3 MAC 位址選擇

| MAC 位址 | 特性 | 用途 |
|---------|------|------|
| `01:1B:19:00:00:00` | Forwardable | 1588 default profile（L2 E2E） |
| `01:80:C2:00:00:0E` | Non-forwardable（保留） | P2P delay、802.1AS 所有訊息 |

- UDP/IPv4 的 multicast 會被 **IGMP snooping** 處理
- L2 default profile 用 forwardable MAC，可穿透一般 switch
- 802.1AS 強制使用 non-forwardable MAC，**逐跳停下**重新 timestamp

### 5.4 two-step 強制

- 802.1AS 規範 follow-up 必須攜帶 **cumulative rate ratio** 與 **path trace TLV**
- 即使硬體支援 one-step，配置 `assume_two_step 1` 強制走 two-step 流程
- 目的：精準累積整條路徑上的 rate 誤差

## 六、ptpd 原始碼中的對應實作位置

| 功能 | 檔案路徑 |
|-----|---------|
| Transport enum 定義 | `src/dep/constants_dep.h` |
| UDP/IPv4 socket 實作 | `src/dep/net.c` → `netInit()` / `netSendEvent()` |
| L2 Ethernet socket 實作 | `src/dep/net.c` → `AF_PACKET` / `SOCK_RAW` 分支 |
| transportSpecific 過濾 | `src/dep/msg.c` → `msgUnpackHeader()` |
| delayMechanism 分流 | `src/protocol.c` → `doState()` |
| Multicast 位址設定 | `src/dep/net.c` → `DEFAULT_PTP_DOMAIN_ADDRESS` |

## 七、快速決策指南

```
需要跨路由同步？
├─ Yes → UDP/IPv4（或 UDP/IPv6）
└─ No  → 需要 TSN/AVB/車載 ?
         ├─ Yes → IEEE 802.1AS (gPTP)
         └─ No  → IEEE 802.3 L2
                  ├─ Power grid → 加 Power Profile
                  └─ 一般 LAN 高精度 → default profile
```
